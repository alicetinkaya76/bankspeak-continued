---

This study uses two document collections and deposits everything it is lawfully
permitted to share.

**World Bank material** is publicly available from the World Bank's Documents &
Reports service. The deposit contains the source identifiers, retrieval dates,
request logs, write-once raw API captures, and the frozen sampling frames and
scripts needed to reconstruct the World Bank corpus from that service.

**IMF Article IV staff reports** are third-party materials obtained under written
permission from the International Monetary Fund dated 2026-08-20. That permission
allows analysis and the publication of derived non-substitutive outputs,
including counts and SHA-256 hashes, but prohibits redistribution of the reports
and of extracted document text. I therefore deposit no IMF document and
no extracted text.

**Access, stated as the evidence supports it.** The written permission of
2026-08-20 governs bulk retrieval and redistribution. It does not govern access,
because the IMF publishes these reports. They are served from the Fund's own
website without credentials (no subscription and no application), and all 1,064
documents analysed here were fetched from `www.imf.org` at HTTP 200 by an
unauthenticated client. A reader locates a given report by its country and
report number, or by the DOI, which identifies the document and redirects to its
eLibrary landing page rather than to the PDF. We do not write "no gatekeeper":
the next paragraph reports bot management that this study met, and the phrase
would contradict our own measurements.

**Automated retrieval is a different matter, and I report what I met rather
than what would be convenient.** Its failures are silent: an absent report
redirects to an error page served at HTTP 200 with `text/html`, so a status code
alone reports success for a document that is not there. A byte-checked probe of
20 sampled documents on 2026-08-29 found the static path serving a real PDF for
16, an error page for four, and the DOI resolving to a document for none. The IMF's site is bot-protected: on
2026-08-20 the CMS pages returned HTTP 403 to an identified research client and
`doi.org`/`elibrary.imf.org` returned HTTP 202 with an empty body, while static
document paths served PDFs. Our own retrieval of the 1,064 documents therefore
needed a documented ladder: **705 came from legacy static paths, four from the
CMS media tree, one from a bounded verification-gated sequence, and 354 from the
media-tree link the IMF itself published on the report's own page, read out of a
public web-archive snapshot of that page because the live page is WAF-blocked.
Every one of the 1,064 PDFs was then fetched from `www.imf.org`, and
none was taken from the archive** (`tools/retrieval_route_tally.py` regenerates
this from the retrieval manifest, whose bytes are deposited by hash only because
they carry IMF document URLs, whereas the published index carries report number,
year, country, DOI and SHA-256 for all 1,064). A researcher scripting the same
collection should expect the same friction. Every measurement reported here was
made by an identified non-browser client, and the block we met is bot management
on the CMS and eLibrary paths rather than an access control on the documents.
But we did not probe the site with a browser, so we do not assert what a human
reader meets.

The deposit carries the five files the table and figure generators read, so that
"each numbered table and figure is regenerated by a named command" is a claim a
reader can execute rather than accept. Four travel unchanged. The fifth, the
frozen sampling frame, is deposited with three columns removed
(`display_title`, `txturl` and `pdfurl`), because for the 1,064 IMF rows those
carry verbatim titles and imf.org document URLs, which the permission forbids
redistributing. **The columns are dropped for every row, not only the IMF ones**,
because no generator reads any of the three and a whole-column rule cannot leak
through a misclassified row. The unredacted original is listed in the manifest by
SHA-256, so a holder of the licensed material can still confirm byte identity
with the file we analysed. Unpacking the deposit into `data/` and running
`python tools/make_paper_tables.py` reproduces all seven tables byte-for-byte.
This was verified, not assumed.

To make the corpus identifiable either way, `data/meta/imf_document_index.csv`
lists all 1,064 documents by **report number, year, country ISO3, DOI and
SHA-256**. Whatever route a reader uses, hashing the retrieved file against that
index confirms byte identity with the copy analysed here before any stage is
rerun. Seven documents carry no DOI and are located by country and report number.
The corresponding author is not the decision-maker for access and can neither
grant nor withhold it.
