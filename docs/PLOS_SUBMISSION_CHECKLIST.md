# PLOS ONE submission checklist — measured, not assumed

Every limit below was read from the journal's own pages on **2026-08-29** and is
quoted. Every measurement was made by `tools/plos_compliance.py`, which runs in
the test suite, so a later edit that breaks a limit fails a test instead of
reaching an editor.

Run it:

```bash
python tools/plos_compliance.py
```

---

## The rule that reorders everything else

> "PLOS ONE waives all formatting requirements until your manuscript has
> received a provisional Editorial Accept decision."
> — `journals.plos.org/plosone/s/getting-started`

So there are two lists, not one. **Blockers** bind now, because they are fields
in the submission form or rules a desk screen applies. **Accept-stage** items are
real requirements that are waived until the paper is provisionally accepted;
doing them now would be work invested in a manuscript that may never need it,
and would be redone anyway if review changes the text.

The one exception is the reference conversion, which is prepared now for a
reason given below.

### What was wrong, and what changed

**The abstract was 374 words against a 300-word limit.** Nothing in the
repository would have caught it, because until now nothing measured it — the
paper had been audited for statistical and citation defects four times and never
once against the venue's own submission form.

It was cut to 300 without dropping a reported number. The two disclosures that
were compressed rather than removed:

- the two preregistered secondary routes, previously named individually
  (HAC(3) *p* = 0.162; document-level QML *p* = 0.033 against a 0.025 Holm
  threshold), now stated as failing both with both *p*-values given;
- `Bankspeak`'s year, removed because PLOS forbids citations in the abstract.
  The work is still named; only the parenthetical year is gone.

The word count is deliberately strict: it splits on whitespace, so the three
spaced em-dashes count as words. The prose count is 297.

## Accept-stage — prepared, not applied

### References → numbered Vancouver

`docs/REFERENCES_vancouver.md`, generated by `tools/make_vancouver_refs.py`.
**31 of 35 entries resolved from Crossref**; the three conference papers and the
Stanford Literary Lab pamphlet have no DOI, carry verified stable URLs instead,
and are marked for hand entry, keeping their place in the numbering. The count
went from 34 to 35 in round 20, when the Moretti and Pestre record — which named
two separate publication objects under the *New Left Review* DOI — was split.

Audited by `tools/audit_citations.py`: all 35 entries parsed, 31 resolved
against Crossref, and every entry is cited in the body with no in-text
citation missing from the list. First author matches on all 31; **the year
matches on 30** — Lopez Bernal (2017) resolves to a 2016 online-first record,
which is a Crossref print-versus-online artifact and not a citation defect.
The tool exits 0 only when no problem falls outside its five documented
non-defects; it used to exit 1 on every run, which made its exit code
uninformative.
This paragraph used to sit at the head of the manuscript's reference list. An
external review objected that metadata resolution is not evidence that a
source supports the proposition it is cited for, which is right, and that a
bibliography is not the place for a QA report, which is also right. It lives
here instead, and `tools/check_stated_counts.py` reads its two numbers from
this file.

Those three numbers are checked, not typed: `tools/check_stated_counts.py` reads
them out of this file and refuses if they disagree with the audit object. They
had drifted to "23 of 25" and nothing noticed until an external reviewer counted
the reference list by hand.

This one is built ahead of time on purpose. The predecessor paper from this
project was rejected partly for citations that had drifted from their sources,
and retyping thirty-four references into a second format at the end of a review,
under a deadline, is precisely the situation that produces that. The conversion
is therefore a command whose input is the publisher's metadata, not a typing job.

Two things the generator will not do, and says so in its output:

- **Crossref is not always right about titles.** The Moretti and Pestre record is
  deposited as "Bankspeak" with the subtitle dropped; the manuscript's entry is
  fuller. The tool flags short titles rather than accepting them.
- **Article-title capitalisation** follows whatever the publisher deposited and
  is not normalised to Vancouver sentence case. Automatic title repair is how a
  citation drifts.

### Title → sentence case

> "Titles should be written in sentence case (only the first word of the text,

Current (title case, 125 chars):

**Short title** (limit 100 characters). Entered in the submission form; the text

60 characters.

### Manuscript file

The manuscript is Markdown, built to PDF through LaTeX by
`tools/build_submission_pdf.py`. PLOS accepts a PDF for a LaTeX manuscript and
enforces three things on the file at initial submission, all now in the build:
continuous line numbers, double spacing, page numbers. The supplement is
supporting information and is single-spaced.

Checked against the live submission guidelines on 2026-09-03:

- Title 250 characters or fewer: yes. Abstract 300 words or fewer: yes.
- Required opening order (title page, abstract, introduction) and closing
  order (acknowledgments, references, supporting-information captions): yes.
  The middle sections keep their own names, which the guidelines allow.
- AI-use disclosure in a dedicated methods subsection: §5.1.
- Figure files: separate, TIFF at 300 dpi (`docs/figures/*.tif`, LZW), with
  each caption placed after the paragraph that first cites it, labelled
  "Fig N." as PLOS writes it.
- Supporting information: one file, captioned "S1 Text" at the end of the
  manuscript.
- Funding, competing interests, CRediT, data availability: entered in the
  form, not the file; the text is in `docs/SUBMISSION_FORM_FIELDS.md`.
- Prose: no em dashes, no semicolon-joined clauses; the pass is verified by
  a script that refuses on any remaining instance outside tables, code and
  citation groups.
- References: still author-year in the text and grouped in the list. The
  numbered Vancouver list is generated and ready (section above); the in-text
  conversion is deferred to acceptance, where PLOS applies formatting, because
  it touches about eighty citations and one of them (Moretti and Pestre 2015)
  now resolves to two publication objects that a person must assign.

## One criterion worth reading twice

> "If a submitted study replicates or is very similar to previous work, authors
> must provide a sound scientific rationale for the submitted work and clearly
> reference and discuss the existing literature."
> — `journals.plos.org/plosone/s/criteria-for-publication`

This paper is a **reconstruction**, not a replication — the original corpus
and rules were never released, so nothing can be replicated in the strict sense.
The clause still applies to a reconstruction of a published result, and is not
optional. The rationale is already in both places it needs to be: §1 and §2 of
the manuscript, and the cover letter's second paragraph — the original corpus,
feature definitions and assembly rules were never released, so the finding has
been discussed far more often than checked. Nothing to add; noted so that it is
not discovered as a surprise.

## Where the quartile stands

PLOS ONE is reported **Q2 in Multidisciplinary Sciences** (2025 JCR, JIF 2.8) by
several secondary aggregators, which agrees with the assumption in
`VENUE_FINAL_20260828.md` and gives **20 ÜAK points**, not 30. **This is
secondary-sourced.** Journal Citation Reports itself is paywalled and was not
opened, so if the twenty-versus-thirty difference matters to the application,
confirm it through an institutional JCR subscription before submitting.

## The submission PDF

```bash
python tools/build_submission_pdf.py --both
```

Builds `build/submission/PLOS_ONE_submission.pdf` — 59 pages — and, with
`--both`, `build/submission/PLOS_ONE_supplement.pdf` at 20 pages. The
supplement went through seventeen rounds as raw Markdown. PLOS publishes
supporting information in whatever format it is given, so that would have
shipped untypeset and, worse, without the glyph check below — and the
supplement carries more Greek and more superscripts than the manuscript
does. It is built through the same path for that reason.

The manuscript build has figures embedded
with captions, from the Markdown source rather than from a second hand-maintained
copy. PLOS's format-free route takes exactly this: one PDF with the text and the
figures in it.

**It reads the PDF back and refuses to call it done if a glyph is missing**,
which is not a precaution but a repair. XeLaTeX does not fail on a character its
font cannot set; it writes a notdef and carries on. Two rounds of that happened
here:

- Times New Roman has no U+2079, so **"2⁹ = 512" was typeset as "2 = 512"** — the
  statement of the bootstrap's support becoming an arithmetic falsehood, in a
  build that reported success.
- The estimand is written inside a code span, so it is set in the *monospace*
  font, and the default has no Greek. The line defining the whole design,
  `log E[count_it] = year FE + γ·WB + τ·(WB × centred year) + β·(WB × post)`,
  **came out with all three coefficients deleted.**

Both are now impossible to ship: super- and subscripts are rewritten as LaTeX
math, fonts are chosen by rendering a Greek sample and reading it back rather
than by loading successfully, and the finished PDF is scanned for notdefs and for
seven load-bearing strings before the build reports success.

The title page carries the author name from a constant in the generator. An
earlier version of this sentence said it came from `CITATION.cff`; there is no
such file in this tree — the public export writes one, and the PDF builder reads
neither. The build leaves the **affiliation and ORCID as visible
placeholders**. They are not invented, and they are visible so they cannot be
uploaded unnoticed.

"Visible" was doing less work than it sounds. `tools/placeholder_report.py`
read the two manuscript Markdown files, the brackets are injected into the
built title page and appear in neither, so the guard printed a clean bill
while page one of the upload carried both. It now reads the rendered PDF and
exits 2 — a distinct code meaning correct as built, not submittable yet —
until they are filled.

## Round 15 changed what "ready" means

An adversarial pre-submission review (`ROUND15_PRESUBMISSION_REVIEW.md`, response
and independent verification in `ROUND15_RESPONSE.md`) found six defects, none of
them in the confirmatory analysis and all of them in what an editor touches
first. Four are fixed; the open ones are listed at the end of the response.

The commands that now guard this, all in the suite except the last two:

```bash
python tools/plos_compliance.py                    # the venue's stated limits
python tools/placeholder_report.py                 # unfilled fields, wrapped ones too
python tools/block_origin_enumeration.py           # Table 5c, all three origins
python tools/retrieval_route_tally.py              # 705/4/1/354, documents not rows
python tools/check_deposit_covers_generators.py    # REFUSES today, by design
```

`check_deposit_covers_generators.py` **now exits 0.** It was written to refuse
while five generator inputs were in no deposit list; the licence question behind
that was decided on 2026-08-30 and is recorded in `ROUND15_RESPONSE.md`. Four of
the five travel unchanged; the frozen sampling frame is deposited with
`display_title`, `txturl` and `pdfurl` dropped, because those carry verbatim IMF
titles and document URLs and no generator reads them. The deposit was then
unpacked and the promised command run against it: all seven tables came out
byte-identical.
